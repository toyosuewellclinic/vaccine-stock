# ワクチン在庫ウィジェット（`index.html`）

ホームページに iframe で埋め込む1枚もの。ビルドも依存も無い素の HTML/JS。
読み込み時に Supabase の `public_vaccine_stock` ビューを取得し、国産・輸入の2表を描く。

## 仕組み

```
index.html
  └ DOM[] … 国産ワクチンの品目リスト
  └ IMP[] … 輸入ワクチンの品目リスト
        ↓ 各品目の k（在庫キー）で照合
  Supabase /rest/v1/public_vaccine_stock
        → name, category, stock, min_stock, unit, updated_at
```

品目リストは **HTML の中に直接書いてある**。Supabase 側は在庫数だけを持ち、
表示する品目・並び順・価格はこのファイルが決めている。だから価格改定や品目追加は
このファイルの編集になる。

各エントリの意味:

| キー | 中身 | 例 |
| --- | --- | --- |
| `v` | ワクチン名（一般名）。表の1列目 | `帯状疱疹ワクチン` |
| `b` | 商品名。表の2列目。無ければ空文字 | `シングリックス` |
| `k` | **Supabase 側の在庫キー**（`inventory_products.name`）。省略時は `v` で照合 | `帯状疱疹ワクチン(シングリックス)` |
| `p` | 価格。表示用の文字列 | `22,000円(税込)` |

`v` / `b` と `k` を分けてあるのは、表示上の名前と在庫管理システム上の商品名が
一致していないため。ここを1つにまとめようとすると在庫が引けなくなる。

在庫数の表示は `stock` と `min_stock` で決まる:

| 条件 | 表示 | 色 |
| --- | --- | --- |
| `stock === 0` | `終了` | 赤 |
| `stock < min_stock` | 数量 + 単位 | オレンジ（少なめ） |
| それ以外 | 数量 + 単位 | 緑 |
| 該当行が無い | `－` | グレー |

Supabase の anon（publishable）キーがファイルに直書きされているが、これは公開前提のもの。
`public_vaccine_stock` ビューの読み取りしかできないので問題ない。
**`service_role` キーをここに書いてはいけない**（書くと在庫テーブル全体が誰でも書き換えられる）。

## 品目を追加・変更する

1. `index.html` の `DOM`（国産）か `IMP`（輸入）の配列に行を足す。表の並び順＝配列の順序。
2. `k` を Supabase の商品名と**完全一致**させる。ここが最重要。
3. `p` は既存の書式に揃える（`16,500円(税込)`、回数があるものは `33,000円(税込/回)`）。
4. ブラウザで開いて、その品目に在庫数が出ることを確認する。`－` のままなら `k` が違う。

価格だけの変更なら `p` を直すだけでよい。

コミットメッセージは既存に倣う（`feat: add メンクアッドフィ (24,000円)` のような形）。

## 在庫が表示されないとき

`－` はエラーではなく「照合できなかった」印なので、**画面には何のエラーも出ない**。
上から順に確認する。

1. **名前の不一致（ほとんどこれ）** … `k` と Supabase の商品名を1文字ずつ比べる。
   全角括弧 `（）` と半角括弧 `()`、スペースの有無、中黒の有無まで一致が要る。
   例: `水痘・帯状疱疹ワクチン（生ワクチン）` は全角括弧、`3種混合(DPT)ワクチン(トリビック)` は半角括弧。
2. **Supabase 側にその行が無い** … ビューに出ているか確認する。
3. **ビューの定義・権限** … 全品目が `－` になるなら通信かキーの問題。ブラウザのコンソールに
   `読み込みエラー` が出ていればそちら。

## 触るときの注意

- **ビルド無し・依存無しを維持する。** フレームワークやビルド手順を持ち込まない。
  1枚のファイルを開けば全部読めることがこのウィジェットの価値。
- **iframe 埋め込みの前提を壊さない。** 描画後に親ウィンドウへ高さを通知している
  （`postMessage({iframeHeight})`）。これを消すとホームページ側で表示が切れる。
- **キャッシュ無効化の meta タグを消さない。** 在庫が古いまま見えるのを防いでいる。
- **画面に出る「◯月◯日 ◯◯:◯◯ 更新」は、データの更新時刻ではなくページを開いた時刻。**
  ビューの `updated_at` は取得しているが表示には使っていない。
  「更新時刻が実データと合っていない」と言われたらこれが原因。直すならその `updated_at` の
  最大値を使うように変える。

## 配信について

リポジトリにデプロイ設定ファイルが無いため、この `index.html` がどう配信されているか
（GitHub Pages なのか、ホームページ側にコピーしているのか）は**リポジトリからは分からない**。
反映方法が関わる作業のときは利用者に確認する。推測で「push すれば反映されます」と言わない。
